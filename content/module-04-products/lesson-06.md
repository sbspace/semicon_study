# Module 4 / Lesson 6
## 연산기가 빨라도 메모리를 기다리는 이유

이제 계산하는 쪽과 기억하는 쪽을 모두 봤어. 둘을 연결하면 질문 하나가 남지.

> “연산기는 엄청 빠른데, 왜 실제 작업은 느릴까?”

계산할 데이터가 아직 도착하지 않았을 수도 있어. 오늘은 창고의 크기와 데이터가 나오는 속도를 나누어 볼 거야.

## 오늘 목표는 딱 하나야

> **얼마나 많이 담는지, 얼마나 많이 옮기는지, 얼마나 기다리는지는 서로 다른 문제야.**

## 1. 창고가 크다고 출입문도 넓을까?

**용량**은 얼마나 많은 정보를 담을 수 있는지, **대역폭**은 일정 시간에 얼마나 많은 데이터를 전달할 수 있는지, **지연 시간**은 요청에서 필요한 데이터가 도착하기까지의 기다림이야. **병목**은 전체 진행 속도를 제한하는 구간이야.

창고가 크다고 출입문이 넓은 것은 아니야. 출입문을 넓혔다고 창고까지 가는 길이 짧아지는 것도 아니야.

저장량, 운반량, 첫 도착 시간은 서로 다른 문제야.

CPU·GPU·NPU에 연산 회로가 많아도 입력이 도착하지 않으면 계산을 할 수 없어. 그래서 제품 성능을 볼 때 연산기뿐 아니라 데이터를 어디에 두고 어떻게 공급하는지 봐야 해.

## 2. 계산 시간보다 기다리는 시간이 길다면?

계산기를 빠르게 만들었는데도 시간이 별로 줄지 않는 이유를 숫자로 확인해보자. 이동과 계산을 따로 적는 게 핵심이야.

**메모리 계층**은 접근 특성과 비용이 다른 기억 공간을 여러 단계로 배치하는 것이야. 코어 가까운 레지스터, 캐시, 주기억장치, 저장장치를 생각하면 돼.

가까운 공간은 대체로 작고, 큰 공간에서는 필요한 데이터를 가까이 가져와 사용해. 모든 접근이 반드시 계층을 한 단계씩 똑같이 통과한다는 뜻은 아니야.

Module 4 Lesson 3에서 같은 가중치를 여러 번 쓰는 장점을 봤지. 이렇게 한 번 가져온 데이터로 더 많은 계산을 하면 데이터 전달 부담을 줄일 수 있어.

반대로 작은 계산마다 새로운 데이터를 많이 읽으면 공급 속도가 중요해져.

<interactive type="memory-hierarchy-bottleneck" />

간단한 상황을 같이 계산해보자. 1GB의 데이터를 가져오는 유효 대역폭이 10GB/s이면 전달에 최소 약 0.1초가 필요해. 이 데이터의 계산 자체는 0.02초라고 해보자.

단위 GB는 여기서 십진 기준이며, 요청 준비 비용은 무시해.

| 가정 | 전체 시간의 해석 |
|---|---|
| 전달 후 계산, 겹치지 않음 | 약 0.12초 |
| 연산만 2배 빨라짐, 겹치지 않음 | 약 0.11초 |
| 반복 작업에서 전달과 계산이 이상적으로 겹침 | 느린 단계가 처리 간격을 제한 |

계산을 두 배 빠르게 해도 0.12초가 0.06초가 되지 않아. 기다림이 남기 때문이야.

실제 시스템의 시간은 데이터 재사용, 여러 요청의 동시 처리, 캐시 사용, 전송과 연산의 겹침에 따라 달라져.

## 3. 앞에서 배운 것과 연결해보자

Module 2의 금속 배선과 내부 연결망은 제품 안에서 데이터와 전력을 전달해. Module 4에서는 그 연결이 처리량을 제한할 수 있다는 의미까지 넓혀서 봤어. 소자 속도 개선이 전체 앱 속도 개선으로 그대로 이어지는 것은 아니야.

## 4. 실제로는 어디에 쓰일까?

DRAM 용량을 늘리는 것은 큰 데이터를 담는 데 도움이 되지만, 다른 조건이 같을 때 전달 속도까지 자동으로 늘려 주지는 않아. 여러 데이터를 동시에 나누어 보내는 연결 구조나 동작 속도도 봐야 해.

Module 7의 HBM은 대역폭을 높이기 위한 메모리 제품이야. 그 전에 Module 5와 6에서 소자와 다이 연결을 개선하는 방법을 살펴볼 것이야.

여기서는 HBM의 구조를 미리 외우지 않아도 돼.

## 5. 잠깐, 네 말로 설명해볼까?

자료가 너무 커서 담기지 않는 경우, 담기지만 연산기가 계속 기다리는 경우, 작은 요청 하나의 응답이 늦는 경우를 각각 어떤 질문으로 구별할까요?

같이 확인해보자. 첫째는 용량, 둘째는 데이터 공급 대역폭이나 다른 병목, 셋째는 요청의 지연 시간을 확인해.

겉으로 보이는 현상만으로 원인을 하나로 확정하지 않고, 데이터를 주고받는 구간과 시간부터 나누어 봐.

## 오늘 핵심 용어

| 용어 | 이 수업에서의 뜻 |
|---|---|
| 용량 | 저장할 수 있는 데이터의 양 |
| 대역폭 | 시간당 전달할 수 있는 데이터의 양 |
| 지연 시간 | 요청에서 결과 도착까지 걸리는 시간 |
| 병목 | 전체 진행 속도를 제한하는 구간 |

## 오늘 반드시 기억할 3줄

**① 큰 용량, 높은 대역폭, 짧은 지연 시간은 서로 다른 장점이야.**

**② 연산과 데이터 이동을 함께 봐야 실제 성능을 이해할 수 있어.**

**③ 재사용과 가까운 기억 공간은 데이터 이동 부담을 줄일 수 있어.**

## 오늘의 Quiz

**Q1. 1GB를 10GB/s로 전달하면 준비 비용을 제외한 최소 시간은?**

**Q2. 전달 0.1초 뒤 계산 0.02초를 해. 계산만 두 배 빨라지면 총시간은?**

**Q3. 메모리 용량이 두 배면 대역폭도 반드시 두 배일까?**

## 정답과 해설

**Q1**

0.1초야. 데이터 양을 초당 전달량으로 나눠.

**Q2**

0.11초야. 전달은 0.1초로 남고 계산이 0.01초가 돼.

**Q3**

아니야. 저장량과 데이터 통로의 전달 능력은 별개야.
