# Module 4 / Lesson 2
## GPU는 왜 같은 일을 많이 처리하는 데 유리할까?

지난 시간에는 CPU가 명령을 읽고 계산하고 결과를 보관하는 흐름을 봤어.

그럼 계산할 게 1개가 아니라 1,000개라면 어떨까?

> “작업자를 많이 두면 빨라지는 거 아니야?”

맞아. 그런데 나눠서 해도 되는 일인지부터 봐야 해. 오늘은 그 차이로 GPU를 이해해보자.

## 오늘 목표는 딱 하나야

> **GPU는 많은 데이터에 비슷한 계산을 나눠 적용할 때 강점이 있어.**

## 1. 도시락 1,000개를 만든다고 생각해봐

**병렬 처리**는 여러 작업을 동시에 진행하는 것이야. **처리량**은 일정 시간에 끝내는 작업의 양이고, **지연 시간**은 한 작업이 결과를 얻기까지 걸리는 시간이야.

둘 다 “빠르다”와 관련되지만 같은 뜻은 아니야.

한 사람이 복잡한 주문을 처리하는 가게와, 여러 작업대가 비슷한 도시락을 동시에 만드는 공장을 떠올려 봐. 도시락 1,000개를 만드는 데는 작업대가 많은 공장이 유리해.

반대로 첫 주문의 결과에 따라 다음 주문 내용이 계속 달라진다면, 작업대가 많아도 기다리는 시간이 생겨.

GPU는 그래픽 처리에서 출발한 처리장치이며, 많은 데이터에 비슷한 연산을 적용하는 높은 처리량의 작업에 잘 맞아. 그렇다고 어떤 프로그램이든 CPU보다 빠른 것은 아니야.

## 2. 화면의 점들을 여러 작업대에 나누면?

여기서 잠깐. 작업대가 많다는 것과 모든 일이 빨라진다는 것은 왜 다를까?

아래 예에서 앞사람의 답을 기다리는 일이 있는지 봐봐.

화면을 구성하는 작은 점을 **픽셀**이라고 해. 픽셀 여러 개에 밝기를 더하는 단순 예를 볼게.

각 픽셀의 기존 밝기를 읽고 10을 더하는 작업은 다른 픽셀의 결과를 기다리지 않고 계산할 수 있어.

| 작업 | 입력 | 연산 | 출력 |
|---|---|---|---|
| 픽셀 A | 20 | 10 더하기 | 30 |
| 픽셀 B | 40 | 10 더하기 | 50 |
| 픽셀 C | 70 | 10 더하기 | 80 |

GPU에는 이런 연산을 나누어 처리할 많은 실행 자원이 있어. 여러 실행 자원이 제어와 데이터 공급 자원을 공유하기도 해.

그래서 각 작업이 전혀 다른 경로로 흩어지거나 데이터를 충분히 공급받지 못하면 효율이 떨어질 수 있어.

<interactive type="cpu-gpu-parallelism" />

그림 없이도 이렇게 생각하면 돼. 독립적인 계산 네 개는 네 작업대에 나눌 수 있지만, `A 결과 → B 입력 → C 입력`처럼 앞의 답이 다음 문제의 재료인 작업은 그 순서를 지켜야 해.

숫자를 간단히 놓고 볼게. 계산 100개가 각각 1초이고, 완전히 독립적이며, 작업대 10개에 균등하게 나뉜다고 해보자.

이동과 준비 시간이 없다면 10초야. 준비에 5초가 들면 15초가 돼.

이 단순 계산이 실제 GPU의 속도를 예측하는 공식은 아니야. 병렬화 이득에도 준비·전달 비용이 있다는 점을 보여 줘.

## 3. 앞에서 배운 것과 연결해보자

CPU와 GPU는 모두 소자, 논리 회로, 기억 회로를 사용해. 차이는 자원 배치와 실행 방식이야. CPU도 병렬 처리를 하고 GPU도 제어 회로를 가져. GPU 안의 작은 연산 단위를 CPU 코어 하나와 숫자만으로 일대일 비교해서는 안 돼.

현재 위치는 “회로를 어떤 처리 구조로 묶어 제품을 만들까”야. Module 3의 공정으로 같은 종류의 기본 소자를 만들더라도, 설계가 달라지면 다른 제품이 돼.

## 4. 실제로는 어디에 쓰일까?

그래픽 처리, 많은 수에 대한 반복 계산, 일부 인공지능 계산은 GPU 활용에 잘 맞아. **인공지능 모델**은 입력에서 결과를 계산하도록 구성하고 학습시킨 계산 규칙과 수치의 묶음이야.

다음 Lesson에서는 그중 반복되는 특정 계산을 더 집중적으로 처리하는 NPU를 봐.

## 5. 잠깐, 네 말로 설명해볼까?

① 사진 1,000장의 밝기를 각각 조정하기, ② 첫 계산의 답으로 다음 계산의 주소를 정하는 작업. 어느 쪽이 여러 작업대로 나누기 쉬울까요?

①이 더 직접적으로 나뉘어. ②는 앞 결과를 기다리는 관계가 병렬성을 제한해. 실제 사진 처리에서도 파일 읽기와 결과 저장이 느리면 계산 자원을 더 늘려도 전체 시간은 충분히 줄지 않을 수 있어.

## 오늘 핵심 용어

| 용어 | 이 수업에서의 뜻 |
|---|---|
| GPU | 많은 데이터의 병렬 연산에 적합한 처리장치 |
| 병렬 처리 | 여러 작업을 동시에 진행하는 방식 |
| 처리량 | 일정 시간에 완료하는 작업의 양 |
| 지연 시간 | 한 작업의 결과를 얻기까지 걸리는 시간 |

## 오늘 반드시 기억할 3줄

**① GPU는 많은 비슷한 작업을 나누어 처리할 때 강점이 있어.**

**② 독립성, 데이터 공급, 준비 비용을 함께 봐야 해.**

**③ GPU의 연산 자원 수와 CPU 코어 수를 직접 비교하면 안 돼.**

## 오늘의 Quiz

**Q1. 독립 작업 100개, 작업대 10개, 작업당 1초, 준비 5초라면 교육용 가정의 총시간은?**

**Q2. 연산 자원을 두 배로 늘리면 모든 프로그램이 두 배 빨라지는가?**

**Q3. GPU의 높은 처리량은 한 작업의 지연 시간이 언제나 CPU보다 짧다는 뜻일까?**

## 정답과 해설

**Q1**

15초야. 계산 100÷10=10초에 준비 5초를 더해.

**Q2**

아니야. 순서 의존성, 데이터 공급과 준비 시간이 남아.

**Q3**

아니야. 처리량과 지연 시간은 다른 지표야.
