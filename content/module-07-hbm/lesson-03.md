# Module 7 / Lesson 3
## 8H·12H와 GB·TB/s를 따로 읽기

HBM 제품 이름을 보면 8H, 12H, GB, TB/s 같은 숫자가 함께 나와.

> “층을 더 쌓으면 용량도 늘고 속도도 똑같이 늘겠지?”

여기서 잠깐 멈춰야 해. 더 많이 담는 것과 더 많이 내보내는 것은 달랐지? 오늘은 숫자를 직접 나눠 읽어보자.

## 오늘 목표는 딱 하나야

> **적층 수는 저장 용량과 연결하고, 외부 대역폭은 데이터 통로와 전송률로 따로 계산해.**

## 1. 창고 층을 늘려도 출입문은 그대로일 수 있어

HBM의 **8H**, **12H** 같은 표기는 일반적으로 쌓인 DRAM 다이의 개수를 가리켜. 아래 베이스 다이를 별도로 생각해.

실제 제품 문서를 읽을 때도 표기의 정의를 확인해.

8층 창고를 12층으로 늘리면 물건을 더 많이 둘 수 있어. 그러나 출입문 폭과 차량 속도를 그대로 두면 초당 나갈 수 있는 물건 수는 그대로일 수 있어. HBM도 저장 공간을 늘리는 것과 외부 데이터 통로를 넓히는 것을 구별해.

앞 Lesson에서 HBM이 여러 다이로 구성됨을 봤지. 이제 층 하나의 저장량과 스택 전체의 저장량을 나누어 읽어보자.

## 2. 다이 한 장의 용량부터 합쳐보자

먼저 저장량만 계산할 거야. 이 계산에는 초당 속도가 들어가지 않는다는 점을 봐봐.

**Gb**는 기가비트, **GB**는 기가바이트야. 같은 접두 기준에서 8bit가 1byte이므로 24Gb는 3GB야.

숫자를 간단히 놓고 볼게. 모든 DRAM 다이의 데이터 용량이 24Gb이고, 단순히 합산할 수 있다고 가정해.

| DRAM 다이 수 | 계산 | 스택 데이터 용량 |
|---:|---|---:|
| 8 | 24Gb × 8 ÷ 8 | 24GB |
| 12 | 24Gb × 12 ÷ 8 | 36GB |
| 16 | 24Gb × 16 ÷ 8 | 48GB |

이는 산술 예제이며 특정 제품의 내부 예비 영역이나 오류 보호 방식을 추정하는 계산이 아니야. 제품 사양표에 제공된 사용 가능한 용량을 우선해.

베이스 다이가 있다고 DRAM 한 장분의 용량을 덧붙이지 않아.

그럼 8H에서 12H로 바꾸면 대역폭도 1.5배일까요? 외부 데이터 폭과 핀당 전송률이 같다면 앞 Lesson의 최대 대역폭 식은 바뀌지 않아.

내부 병렬성이나 접근 효율의 차이가 생길 수는 있지만, 층 수를 그대로 외부 대역폭의 곱셈 항으로 넣지는 않아.

## 3. 스택 여러 개를 쓰는 경우

연산기 옆에 HBM 스택을 여러 개 배치하고 각각을 사용할 수 있는 인터페이스가 있다면, 총 용량은 스택 용량을 합해 생각할 수 있어. 이론 대역폭도 각 독립 인터페이스의 대역폭을 더할 수 있어.

예를 들어 24GB, 512GB/s의 가상 스택 네 개라면 총 96GB이고 이론 합은 2,048GB/s야. 다만 프로그램이 네 스택을 충분히 고르게 활용하고 연산기 쪽 연결도 지원해야 해.

스택 숫자만으로 실제 성능을 확정하지 않아.

## 4. 앞에서 배운 것과 연결해보자

Module 4의 메모리 계층에서는 저장량, 접근 시간, 이동량을 따로 봤지. HBM 사양에서도 같은 원칙이 적용돼. 큰 모델이 메모리에 들어가는지는 용량 문제이고, 들어간 데이터를 충분히 빨리 공급하는지는 대역폭 문제야.

## 5. 실제로는 어디에 쓰일까?

층을 늘리면 다이를 더 얇게 만들거나 접합부 높이를 조정해야 할 수 있어. 패키지 높이와 기계적 안정성, 열 전달, 검사 부담이 함께 달라져.

“같은 바닥 면적에서 더 많은 저장량”이라는 장점과 제조 통합 문제를 같이 읽어.

그래서 사양표는 세 줄로 나누어 읽으면 좋아. 첫째 한 스택의 용량과 높이, 둘째 인터페이스의 대역폭, 셋째 제품 전체의 스택 수야.

이 세 정보를 섞지 않으면 숫자 비교가 쉬워져.

## 6. 잠깐, 네 말로 설명해볼까?

A는 24GB·512GB/s, B는 36GB·512GB/s인 가상 스택이야. 30GB 데이터가 필요한 작업에서 B가 주는 이점과, 무조건 보장하지 않는 이점을 각각 적어봐.

같이 확인해보자. B는 필요한 데이터를 한 스택에 담을 수 있어. 하지만 외부 최대 대역폭은 같으므로 모든 계산이 1.5배 빨라진다고 말할 수 없어.

실제 제품에서는 여러 메모리를 함께 쓰는 구성도 확인해.

## 오늘 핵심 용어

| 용어 | 이 수업에서의 뜻 |
|---|---|
| 8H / 12H | 일반적으로 DRAM 다이 8개 / 12개를 쌓았다는 표기 |
| Gb / GB | 기가비트 / 기가바이트 |
| 스택 용량 | 한 HBM 스택이 제공하는 저장량 |
| 총 대역폭 | 독립 인터페이스 대역폭을 합한 이론적 전달 능력 |

## 오늘 반드시 기억할 3줄

**① 다이당 용량과 적층 수가 스택 용량의 출발점이야.**

**② 적층 수를 외부 대역폭 식에 다시 곱하지 않아.**

**③ 스택당 사양과 제품 전체 합계를 구별해.**

## 오늘의 Quiz

**Q1. 24Gb DRAM 12장을 합한 교육용 용량은?**

**Q2. 데이터 폭과 핀당 속도가 같은데 8H를 12H로 바꾸면 외부 최대 대역폭은 반드시 1.5배일까?**

**Q3. 가상 24GB 스택 네 개의 용량은?**

## 정답과 해설

**Q1**

36GB야. 24×12÷8=36이야.

**Q2**

아니야. 층 수는 그 식의 곱셈 항이 아니야.

**Q3**

96GB야. 접근 방식이나 실제 처리 속도까지 이 합계만으로 결정되지는 않아.
