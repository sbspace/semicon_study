# Module 7 / Lesson 4
## HBM의 병목은 어디에 남을까?

이제 HBM의 넓은 통로와 적층 구조를 이해했어. 그런데 모든 GPU에 HBM만 붙이면 끝일까?

> “데이터를 많이 보낼 수 있는데 어디서 또 기다려?”

메모리 안에서 꺼내는 과정, 연산기 안쪽, 냉각에 제한이 남을 수 있어. 오늘은 완성된 제품 전체를 보자.

## 오늘 목표는 딱 하나야

> **HBM도 셀·연결·접합·열·데이터 접근이 함께 맞아야 제 역할을 할 수 있어.**

## 1. 도로를 넓혀도 출발지에서 막힐 수 있지?

**병목**은 전체 흐름을 제한하는 구간이야. 넓은 도로를 만들어도 출발지 창고가 물건을 준비하지 못하거나 도착지 하역장이 좁으면 운송량이 충분히 늘지 않아.

HBM은 많은 데이터를 전달하도록 설계한 메모리야. 하지만 데이터가 저장된 위치를 찾아 꺼내고, 연결을 지나 보내고, 연산기가 소비하는 전체 과정 중 어디든 제한이 남을 수 있어.

이 Lesson은 앞의 세 Lesson을 제품과 제조 문제로 연결해.

## 2. 데이터 한 번 읽는 동안 어디서 기다릴까?

외부 통로만 보지 말고 데이터가 준비되는 곳부터 따라가보자. 어느 구간의 문제인지 나누는 연습이야.

**뱅크**는 DRAM 안에서 데이터를 나누어 관리하는 내부 영역이야. 여러 뱅크를 활용하면 요청을 나누어 처리할 여지가 있지만, 같은 자원에 요청이 몰리면 기다림이 생길 수 있어.

세부 타이밍을 외우기보다 “외부 통로가 비어 있어도 내부에서 준비할 일이 있어”는 점을 이해하면 돼.

| 구간 | 기다림이 생기는 예 | 확인할 질문 |
|---|---|---|
| DRAM 내부 | 같은 영역에 요청 집중 | 데이터를 어떻게 배치·접근할까? |
| HBM–연산기 연결 | 데이터 통로를 충분히 활용하지 못함 | 요청 크기와 동시 접근은 적절한가? |
| 연산기 내부 | 계산 또는 내부 이동이 느림 | 외부 메모리만 바꿔 해결될까? |
| 제품 냉각 | 온도로 동작 속도 제한 | 지속 동작 조건이 맞을까? |

이 표는 원인 후보를 나눈 것이며, 현상만 보고 바로 결론을 내리는 진단표는 아니야. 실제 측정으로 구간별 시간을 확인해.

## 3. 제조에서 남는 문제

Module 6의 **KGD**는 조립 전 검사로 양품으로 판정된 다이였어. 불량 다이를 비싼 스택에 넣으면 손실이 커지므로 먼저 검사하는 가치가 커.

그러나 조립 전에 정상이어도 얇게 가공하거나 접합하는 과정에서 새 문제가 생길 수 있어.

<interactive type="hbm-test-thermal" />

TSV 연결, 다이 사이 접합, 외부 패키지 연결이 끊기거나 서로 닿으면 데이터가 정상적으로 오가지 못해. Module 3의 Clean과 CMP에서 배운 표면 청정도와 평탄도가 접합 품질로 다시 연결돼. 내부 메모리 셀과 외부 연결을 둘 다 확인해야 해.

**열저항**은 열이 빠져나가기 어려운 정도를 나타내는 개념이야. 전기저항이 전류 흐름과 관계가 있듯, 열의 이동에도 경로가 중요해.

다이를 쌓으면 안쪽에서 발생한 열의 탈출 경로를 함께 설계해야 해. 실제 온도는 각 다이의 전력, 접합 재료, 냉각 구조 등에 따라 달라져.

## 4. 앞에서 배운 것과 연결해보자

소자의 전기 특성은 DRAM 셀과 인터페이스 동작에 영향을 줘. 공정과 접합은 그 구조를 구현해.

패키지는 데이터를 연결하고 열을 내보내. 제품의 소프트웨어는 데이터를 어떤 순서로 읽을지 결정해. HBM 하나를 이해하는 데 Module 0~6의 여러 층위가 함께 필요한 이유야.

## 5. 실제 제품 선택과의 연결

모든 기기에 HBM이 적합한 것은 아니야. 일반 DRAM 모듈, 그래픽용 GDDR, 패키지에 밀접하게 연결한 HBM은 연결 방식과 용량 구성, 비용 목표가 달라. GDDR도 DRAM 계열이며, HBM만 DRAM인 것은 아니야.

휴대기기나 PC, 고성능 연산 서버의 요구가 다르므로 필요한 공급량과 제품 조건에 맞춰 선택해.

## 6. 잠깐, 네 말로 설명해볼까?

새 제품이 메모리 최대 대역폭을 높였는데 실제 작업 속도는 거의 그대로야. 확인할 질문 세 개를 만들어봐.

같이 확인해보자. 원래 그 작업이 외부 데이터 공급을 기다렸는가?

요청이 여러 내부 자원에 고르게 나뉘는가? 연산·온도·다른 통신 구간에서 제한이 생기는가?

답을 얻기 전에 “HBM이 효과 없다”거나 “GPU가 고장 났다”고 결론 내리지 않아.

아니야. 박막화·접합·조립 중 새 결함이 생길 수 있어.

아니야. 비용·용량·패키지·전력·실제 작업 요구를 함께 봐야 해.
