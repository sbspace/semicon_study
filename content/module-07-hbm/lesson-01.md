# Module 7 / Lesson 1
## HBM은 왜 데이터 통로를 넓힐까?

Module 4에서 GPU가 계산할 재료를 기다릴 수 있다고 했어. Module 6에서는 다이 사이에 연결을 많이 만드는 방법을 봤고.

둘을 붙이면 HBM이 왜 등장하는지 보이기 시작해.

> “GPU 옆에서 데이터를 한꺼번에 많이 보내주면 어떨까?”

## 오늘 목표는 딱 하나야

> **HBM은 GPU 대신 계산하는 부품이 아니라, 많은 데이터를 공급하는 메모리야.**

## 1. 요리사는 많은데 재료 통로가 하나라면?

**HBM**은 High Bandwidth Memory, 즉 높은 대역폭을 목표로 만든 메모리야. **대역폭**은 일정 시간에 옮길 수 있는 데이터의 양이야. HBM은 DRAM을 여러 장 쌓고 많은 연결을 활용하는 제품이며, 전원을 끄면 데이터가 유지되지 않는 휘발성 메모리야.

작업자가 많은 주방에 재료를 한 상자씩만 넣어준다고 생각해보자. 요리사가 손이 빨라도 재료를 기다리면 일을 못 해.

통로를 여러 개 마련하면 한 번에 더 많은 상자를 들여올 수 있어. HBM의 핵심은 이렇게 데이터 공급 통로를 넓히는 데 있어.

Module 4에서 GPU는 비슷한 계산을 많이 나누어 처리한다고 배웠지. 그 많은 연산 자원을 계속 일하게 하려면 입력과 가중치가 도착해야 해. HBM 자체가 GPU 대신 계산하는 것은 아니야.

## 2. 통로 수와 통로 하나의 속도를 곱해보자

대역폭이라는 말을 숫자로 바꿔볼게. 식부터 외우지 말고, 몇 개의 길에서 각각 얼마나 보내는지 생각해봐.

**인터페이스 폭**은 병렬로 데이터를 전달하는 통로의 폭이야. **핀당 전송률**은 데이터 연결 한 개가 초당 전달하는 비트 수야.

**bit(비트)**는 0 또는 1 한 자리, **byte(바이트)**는 8bit야. Gb/s는 초당 10억 비트, GB/s는 초당 10억 바이트야. 핀이라는 표현은 여기서 데이터 신호 연결을 가리키며, 패키지의 모든 전원·접지 연결까지 센 수가 아니야.

단순화한 최대 대역폭은 다음처럼 생각할 수 있어.

`대역폭(byte/s) = 데이터 폭(bit) × 핀당 전송률(bit/s, 연결당) ÷ 8`

계산에서는 폭 1,024를 데이터 연결 개수로 사용해. 8bit가 1byte이므로 마지막에 8로 나눠. 숫자를 간단히 놓고 볼게.

폭이 1,024이고 각 연결이 4Gb/s라면 `1,024×4÷8 = 512GB/s`야. 여기서는 G를 10억으로 쓰며, 특정 판매 제품의 사양을 인용한 숫자는 아니야.

| 가상 설계 | 데이터 연결 수 | 연결당 전송률 | 계산상 대역폭 |
|---|---:|---:|---:|
| A | 512 | 4Gb/s | 256GB/s |
| B | 1,024 | 4Gb/s | 512GB/s |
| C | 512 | 8Gb/s | 512GB/s |

B와 C는 계산상 대역폭이 같아. 하지만 실제 배선 수, 회로 속도, 전력, 연결 거리와 패키지 요구는 달라. HBM은 넓은 인터페이스를 가까운 패키지 연결로 구현하는 방향이야.

계산상 최대값과 실제 프로그램이 얻는 값도 구별해. 읽을 주소를 준비하고 명령을 보내는 시간, 읽기와 쓰기의 전환, 불규칙한 접근 등 때문에 모든 순간을 데이터 전송에 쓰지는 못해.

## 3. 앞에서 배운 것과 연결해보자

Module 6의 인터포저는 다이 사이를 연결하는 중간 구조였어. 많은 선을 가까운 거리에서 연결하는 패키징은 HBM의 넓은 통로를 실제로 만드는 기반이야.

그래서 HBM 성능은 메모리 셀뿐 아니라 연결 구조와 함께 봐야 해.

## 4. 실제로는 어디에 쓰일까?

GPU가 모든 입력을 가까운 캐시에서 반복 사용하면 외부 메모리에 대한 부담을 줄일 수 있어. 반대로 큰 데이터를 계속 새로 읽으면 공급 대역폭이 더 중요해져.

같은 GPU라도 작업에 따라 HBM의 영향이 달라지는 이유야.

**용량**은 얼마나 많이 저장하는가이고, 대역폭은 얼마나 빨리 옮기는가야. 넓은 통로가 창고 크기까지 자동으로 늘려주는 것은 아니야.

첫 데이터를 기다리는 지연 시간도 대역폭과 별도로 봐.

## 5. 잠깐, 네 말로 설명해볼까?

연산기는 초당 1,000개 계산을 할 수 있는데 메모리는 계산 400개분의 재료만 공급한다고 해보자. 연산기만 두 배로 늘리면 어떻게 될까요?

같이 확인해보자. 데이터 재사용 등의 다른 변화가 없다면 공급 한계가 남아.

먼저 실제 작업이 계산을 기다리는지, 데이터를 기다리는지 확인해야 해. 이 예는 원리를 위한 가정이며 실제 GPU 성능 비율을 예측하지 않아.

## 오늘 핵심 용어

| 용어 | 이 수업에서의 뜻 |
|---|---|
| HBM | 높은 대역폭을 목표로 DRAM 적층과 넓은 연결을 활용한 메모리 |
| 대역폭 | 시간당 전달 가능한 데이터 양 |
| 인터페이스 폭 | 병렬 데이터 전달 통로의 폭 |
| 핀당 전송률 | 데이터 연결 한 개가 초당 전달하는 비트 수 |

## 오늘 반드시 기억할 3줄

**② 대역폭은 통로 수와 연결당 전송률을 함께 봐야 해.**

**③ 대역폭·용량·지연 시간은 서로 다른 기준이야.**

## 오늘의 Quiz

**Q1. 가상 폭 512, 연결당 4Gb/s의 최대 대역폭은?**

**Q2. HBM 대역폭이 두 배면 모든 GPU 작업이 두 배 빨라지는가?**

**Q3. GB와 GB/s 중 저장할 수 있는 양을 나타내는 것은?**

## 정답과 해설

**Q1**

256GB/s야. 512×4÷8로 계산해.

**Q2**

아니야. 계산·캐시 재사용·다른 데이터 이동 등 남은 제한 조건에 따라 달라.

**Q3**

GB야. GB/s는 시간당 이동량이야.
