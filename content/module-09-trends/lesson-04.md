# Module 9 / Lesson 4
## 칩렛 연결 표준 — 여러 회사의 다이를 함께 쓰려면

칩렛은 기능을 여러 다이로 나눠 연결하는 방식이었지. 회사들도 일을 나눠 맡는다고 했어.

> “그럼 서로 다른 회사의 다이를 사서 그냥 붙이면 될까?”

물리적으로 붙이는 것뿐 아니라 같은 규칙으로 데이터를 주고받아야 해. 마지막 수업에서는 이 연결과 제품 전체를 함께 볼 거야.

## 오늘 목표는 딱 하나야

> **연결 표준은 공통 기반을 만들지만, 실제 제품 조합의 기능·전력·패키지 조건도 맞아야 해.**

## 1. 플러그 모양이 같으면 모든 게 해결될까?

**UCIe**는 Universal Chiplet Interconnect Express로, 패키지 안의 다이들이 데이터를 주고받는 연결을 표준화하려는 기술이야. **상호운용성**은 서로 다른 구현이 조건이 맞을 때 함께 동작하는 능력이야.

기기의 플러그 모양이 맞으면 연결의 한 문제는 줄어들어. 그래도 전압과 통신 방식, 실제 사용하는 기능이 맞아야 해.

칩렛도 같은 표준 이름을 사용한다고 모든 다이를 아무 조합으로 즉시 조립할 수 있는 것은 아니야.

Module 6에서 칩렛은 기능을 나누어 설계한 다이, 패키징은 그것을 물리적으로 연결하는 기술이라고 배웠지. 이번에는 여러 다이가 같은 규칙으로 정보를 교환하는 문제를 봐.

## 2. UCIe가 정하는 연결 규칙을 보자

Module 6의 접합은 물리적으로 이어주는 일이었지? 이번에는 그 길에서 서로 알아들을 수 있게 하는 약속까지 보는 거야.

UCIe 컨소시엄의 규격 소개는 다이 간 물리 연결과 통신 규칙 등의 범위를 설명해. 공개된 **UCIe 3.0** 소개에는 **48GT/s와 64GT/s** 지원이 제시되어 있어.

이는 규격이 지원하는 전송률 정보이며 모든 출시 제품의 실제 동작 속도를 뜻하지 않아. [UCIe 공식 규격 소개](https://www.uciexpress.org/specifications)

**GT/s**는 초당 10억 번의 전송을 나타내는 단위야. 데이터 연결 수와 부호화·통신에 쓰이는 부가 정보 등을 알아야 실제 사용 가능한 데이터 대역폭으로 바꿀 수 있어. GT/s 숫자를 제품 전체 GB/s로 그대로 읽지 않아.

| 함께 맞춰야 하는 것 | 의미 | 관련 Module |
|---|---|---|
| 물리 신호 연결 | 전기적 신호를 전달 | 소자·배선·패키지 |
| 통신 규칙 | 데이터를 같은 규칙으로 해석 | 회로·시스템 설계 |
| 기능과 관리 | 요청·상태·오류를 함께 처리 | 제품 설계·검증 |
| 조립과 냉각 | 실제로 연결하고 안정적으로 유지 | 공정·패키징 |

<interactive type="chiplet-interoperability" />

표준은 연결의 공통 기반을 마련해. 하지만 다이 크기, 전력·열, 제공 기능, 실제 옵션 지원, 검증과 조립 조건은 제품 설계자가 확인해야 해.

표준의 존재를 이미 완성된 자유 조합 시장으로 확대해석하지 않아.

## 3. 앞에서 배운 것과 연결해보자

Module 2에서는 하나의 칩을 계층과 단면으로 봤고, Module 6에서는 기능을 여러 다이로 나누어 연결했지. Module 8에서는 여러 기업이 역할을 나눴어. 칩렛 표준은 물리적 분할과 기업 간 협업이 만나는 지점이야.

## 4. 실제 시스템 관점 — 계산만 더 빠르면 될까?

전체 연산 제품에서는 칩 내부 계산, HBM 데이터 공급, 다이 간 이동, 다른 보드와의 통신, 전력·냉각이 서로 영향을 줘. 어느 한 구간을 개선하면 다른 구간이 다음 제한이 될 수 있어.

예를 들어 교육용 시스템에서 데이터 이동에 6초, 계산에 4초가 순서대로 걸린다고 해보자. 계산만 두 배 빠르게 하면 전체는 `6+2=8초`야. 10초가 5초가 되는 것은 아니야.

실제 시스템은 겹쳐 실행하기도 하지만 이 예는 “개선하지 않은 부분의 시간도 남는다”는 점을 보여줘.

이것이 Module 0부터 쌓아온 관점이야. 소자 하나의 특성과 회로의 기능, 칩 구조, 공정, 패키지, 제품 전체를 계속 연결해서 봐.

새 기술이 나오면 그 기술이 어느 구간을 바꾸는지 먼저 찾아.

## 5. 잠깐, 네 말로 설명해볼까?

가상의 두 칩렛이 모두 UCIe 지원이라고 해. 바로 함께 주문·조립하기 전에 확인할 질문을 만들어봐.

같이 확인해보자. 지원 버전과 옵션이 맞나?

신호·패키지 조건과 전력·열 조건이 맞나? 서로 필요한 기능을 제공하나?

실제 조합의 검증과 공급은 준비되었나? 표준화의 가치와 제품 통합의 남은 일을 함께 설명해.

## 6. 다음에 이 소식을 다시 읽는다면?

새 규격 버전의 공개, 실제 제품의 지원 범위, 조합별 검증 결과를 구분해 기록해. 규격의 최고 전송률을 제품 전체 성능으로 바꾸지 않아.

이 Lesson의 시스템 병목 설명은 기초 원리에 따른 교육용 해석이며 특정 판매 제품의 측정 결과는 아니야.

## 오늘 반드시 기억할 3줄

**① 표준은 공통 연결 기반을 만들며 실제 조합 검증도 필요해.**

**② 규격 지원 전송률과 제품 전체 대역폭·성능을 구분해.**

**③ 새 기술은 소자부터 제품까지 어느 문제를 줄이는지 평가해.**

## 오늘의 Quiz

**Q1. UCIe 지원만 같으면 모든 칩렛을 바로 조합할 수 있을까?**

**Q2. 64GT/s를 제품 전체 64GB/s라고 읽어도 될까?**

**Q3. 이동 6초+계산 4초인 순차 가상 작업에서 계산만 두 배 빨라지면?**

## 정답과 해설

**Q1**

아니야. 버전·옵션·기능·패키지·전력·검증 등의 조건을 확인해야 해.

**Q2**

안 돼. 전송 단위와 연결 수, 데이터 표현 및 부가 정보 조건이 달라.

**Q3**

8초야. 이동 6초에 계산 2초가 더해져.
