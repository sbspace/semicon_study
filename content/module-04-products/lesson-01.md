# Module 4 / Lesson 1
## CPU는 명령을 어떻게 실행할까?

Module 3에서는 웨이퍼에 소자를 만들고 배선으로 연결하는 과정을 봤지.

그런데 이런 생각이 들 수 있어.

> “트랜지스터가 켜지고 꺼지는 건 알겠는데, 그게 어떻게 프로그램을 실행해?”

오늘은 Module 1의 덧셈기와 레지스터를 다시 꺼내서 CPU 안에 놓아볼 거야. 새로운 마법 부품이 등장하는 게 아니라, 배운 회로들이 역할을 나눠 맡는 거지.

## 오늘 목표는 딱 하나야

> **CPU는 계산할 회로뿐 아니라, 무엇을 계산할지 정하고 결과를 기억할 회로도 함께 갖고 있어.**

## 1. CPU를 작업 지시서를 읽는 사람으로 생각해보자

먼저 **프로그램**은 컴퓨터가 수행할 명령을 정해 놓은 것이고, **명령어**는 하드웨어가 해석해서 실행하는 기본 작업 단위야. CPU는 이런 명령어를 실행하는 중앙처리장치야. 사람이 쓰는 프로그램 한 줄과 CPU 명령어 하나가 항상 같은 것은 아니야.

CPU를 작업 지시서를 읽는 작업자로 생각해보자. “상자 A와 B의 수량을 더해 C에 기록하라”는 지시를 받으면, 무엇을 해야 하는지 읽고, 숫자를 가져오고, 더하고, 결과를 기록해.

계산만 잘해서는 충분하지 않아. 다음에 어떤 지시를 할지도 판단해야 해.

이 비유에서 지시서를 읽는 기능은 제어, 수량을 더하는 기능은 연산, 숫자를 잠시 두는 기능은 기억에 해당해. 실제 CPU는 사람처럼 뜻을 이해하지 않아.

입력된 비트 패턴에 맞춰 회로가 정해진 동작을 해.

## 2. 그럼 CPU 안에서는 누가 무슨 일을 할까?

지시서를 읽는 일, 실제로 더하는 일, 결과를 적어두는 일. 이 세 가지를 나누면 CPU 내부가 훨씬 단순하게 보여.

**코어**는 명령을 실행하는 주요 처리 단위야. 그 안의 **ALU**는 덧셈·논리 비교 같은 연산을 하는 회로야.

**레지스터**는 코어 가까이에서 값을 잠시 보관하는 작은 기억 공간이야. Module 1의 덧셈기와 레지스터가 제품 구조 안에서 다시 등장한 거야.

교육용 CPU에서 다음 순서로 `2 + 3`을 실행한다고 해보자.

| 단계 | 하는 일 | 회로 관점 |
|---|---|---|
| 명령 가져오기 | 더하라는 명령을 읽는다 | 명령이 있는 곳에서 비트를 전달 |
| 해석하기 | 무엇을 어디에 더할지 정한다 | 제어 회로가 연산과 입력 선택 |
| 실행하기 | 2와 3을 더한다 | ALU가 결과 비트를 생성 |
| 결과 보관하기 | 결과 5를 남긴다 | 레지스터 등 목적지에 기록 |

여기서 2와 3을 레지스터에 준비하는 별도의 명령이 있을 수도 있어. 실제 명령의 형식에 따라 달라져.

현대 CPU는 여러 명령의 단계를 겹쳐 실행하기도 하므로, 이 표를 “모든 CPU가 한 번에 명령 하나만 처리한다”는 뜻으로 받아들이면 안 돼.

숫자가 움직이는 길을 한 번 따라가봐. 입력 레지스터에 2와 3이 있고, 제어 회로가 덧셈을 선택하고, ALU 출력 5가 목적 레지스터로 들어가.

클록은 이런 값 전달의 시점을 맞추는 데 쓰여. 클록 한 번이 언제나 명령 하나의 완료를 뜻하지는 않아.

## 3. 앞에서 배운 것과 연결해보자

소자는 전류를 제어하고, 논리 회로는 비트의 관계를 만들고, 연산·기억 회로는 값을 처리해. CPU 코어는 이 회로들을 명령 실행이라는 목적에 맞게 묶은 기능 블록이야. 코어 여러 개와 캐시, 외부 연결 회로가 한 다이 또는 여러 다이에 들어가 CPU 제품을 이룰 수 있어.

## 4. 실제로는 어디에 쓰일까?

컴퓨터에서 파일 이름을 확인하고 조건에 따라 다른 작업을 하는 일은 CPU가 잘 다루는 대표적인 일이야. CPU도 여러 일을 병렬로 실행할 수 있어. 다음 Lesson에서 배울 GPU와의 차이는 “병렬 가능/불가능”보다, 어떤 일을 잘하도록 회로와 자원을 배치했는지에 있어.

설계 관점에서는 같은 덧셈기를 많이 넣는 것만으로 제품이 완성되지 않아. 제어, 데이터 전달, 기억 공간이 함께 맞아야 해.

## 5. 잠깐, 네 말로 설명해볼까?

“결과가 10보다 크면 A 작업, 아니면 B 작업”이라는 지시를 생각해봐. 계산 결과를 잠시 둘 곳, 10과 비교할 곳, 다음 명령을 선택할 기능을 각각 말해 봐.

같이 확인해보자. 레지스터에 결과를 두고, 비교 연산 회로가 조건을 확인하고, 제어 기능이 다음 명령의 흐름을 정해.

특정 실제 CPU의 회로 배치를 그대로 묘사한 예는 아니야.

## 오늘 핵심 용어

| 용어 | 이 수업에서의 뜻 |
|---|---|
| CPU | 명령어를 실행하는 중앙처리장치 |
| 코어 | 명령을 실행하는 주요 처리 단위 |
| ALU | 산술·논리 연산 회로 |
| 레지스터 | 처리 중인 값을 가까이 보관하는 작은 기억 공간 |

## 오늘 반드시 기억할 3줄

**① CPU는 연산뿐 아니라 명령 해석과 실행 흐름 제어를 수행해.**

**② 덧셈기·레지스터 같은 회로가 CPU 코어의 기반이야.**

**③ CPU, 코어, 다이, 패키지는 서로 다른 구분 기준이야.**

## 오늘의 Quiz

**Q1. CPU 안에서 2와 3을 더하는 기능과 결과를 보관하는 기능은 같을까?**

**Q2. 코어가 8개이면 다이도 반드시 8개일까?**

**Q3. 클록 한 번마다 모든 CPU에서 명령이 정확히 하나 완료될까?**

## 정답과 해설

**Q1**

달라. ALU 등의 연산 회로가 계산하고, 레지스터 등의 기억 회로가 결과를 보관해.

**Q2**

아니야. 코어는 기능 단위, 다이는 물리적인 반도체 조각이므로 한 다이에 여러 코어가 들어갈 수 있어.

**Q3**

아니야. 명령 종류와 내부 구조에 따라 실행 시간이 달라지고 여러 명령이 겹쳐 처리될 수도 있어.
