# Module 4 Review — 제품 구조와 CPU/GPU/NPU/SoC/메모리

CPU·GPU·NPU·SoC에 메모리까지 이름이 많이 나왔지? 이제 이름을 따로 외우지 말고, 사진 한 장을 처리하는 기기 안에 역할별로 놓아보자.

정답은 아래에 바로 있어. 먼저 떠올려보고 확인해봐.

## 1. 먼저 큰 그림부터 다시 보자

CPU는 명령 실행을 위한 연산·기억·제어를 묶어. GPU는 나눌 수 있는 많은 작업의 처리량에, NPU는 지원하는 신경망 연산과 데이터 재사용 효율에 강점을 갖도록 설계돼. 세 이름은 기본 재료가 서로 다르다는 뜻이 아니야.

SoC는 이런 여러 시스템 기능을 통합해. 다이는 물리 조각이고, 패키지는 그 조각을 연결하고 보호해. 같은 대상을 기능·설계·물리 구조라는 다른 기준으로 부를 수 있어.

SRAM·DRAM·NAND는 저장 방식이야. 캐시·주기억장치·저장장치는 시스템에서 맡는 역할이야. 연산기가 충분히 일하려면 필요한 용량뿐 아니라 대역폭과 지연 시간도 맞아야 해.

## 2. 이 말들은 꼭 구분하자

| 비교 | 구분 기준 |
|---|---|
| CPU vs 코어 | CPU 제품에는 여러 코어와 다른 기능이 함께 들어갈 수 있어. |
| GPU vs NPU | 병렬 처리와 신경망 최적화라는 설명은 겹칠 수 있어. 제품별 구조와 지원 연산을 확인해. |
| SoC vs 다이 | 통합된 기능과 물리 조각을 구별해. |
| SRAM vs 캐시 | 저장 구현 기술과 데이터 배치 역할을 구별해. |
| 용량 vs 대역폭 | 얼마나 담는지와 얼마나 빨리 전달하는지를 구별해. |

## 3. 지금까지 배운 것과 이어보자

소자에서 논리 회로를 만들고, 논리 회로로 연산·기억·제어를 구현해. 이를 어떤 비율과 연결로 배치하느냐가 제품의 성격을 정해. 제품은 메모리와 연결되어 데이터를 공급받고, 실제 작업에서 가장 느린 구간의 영향을 받아.

다음 Module에서는 이 기능을 더 작은 공간과 적은 전력으로 구현하려 할 때 소자와 공정에 생기는 문제를 다뤄.

## 4. 네 말로 한 번 묶어볼까?

종이에 사진 분류 기기의 구성도를 말로 적어 봐. CPU는 작업을 준비하고, 지원되는 모델 계산을 NPU에 맡기며, 입력과 결과는 메모리에 놓여. 결과 파일을 남긴다면 비휘발성 저장장치를 사용해.

이어 “어디에서 기다릴 수 있을까?”를 추가해. 센서 입력, 데이터 전달, 모델 계산, 결과 저장을 구별하면 좋아. 모범 설명의 핵심은 모든 블록을 한 단어인 ‘칩’으로 뭉뚱그리지 않는 것이야.
